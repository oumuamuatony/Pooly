## 모바일 웹 프로토타입 (2026-11-10)

휴대폰의 기본 제공 형태를 브라우저 웹으로 변경했습니다. 설치 없이 초대 링크로 참가합니다.
기존 Android 차량 앱과 내비 SDK 연결은 그대로 사용합니다. 아래 과거 Android 휴대폰 설명은 이전 구현 기록입니다.

- `web/phone.html`: 기본 접속은 예시 데이터 미리보기. 브라우저 안에만 선택/상태를 보관하며 서버 약속과 실제 위치를 변경하지 않습니다.
- `phone.html?invite=<초대 토큰>`: 같은 서버의 실제 초대에 연결. 참가 전 픽업 위치를 정하고 참가 시 저장합니다.
- 픽업받는 사람만 자신의 장소를 선택/변경합니다. 운전자는 여정에서 읽기 전용으로 확인합니다.
- 화면: 홈, 초대/이동 방식, 내 픽업 위치 선택, 준비/도착/탑승 상태, 전체 여정, 알림, 위치 공유 설정.
- 지도: 휴대폰에만 MapLibre + OpenFreeMap. 장소 검색은 키가 없으면 저장된 장소 목록을 검색하고, 지도 직접 선택도 지원합니다. 전국 장소 검색은 아직 API 키가 필요합니다.
- 시연 상태 전환은 수동이며 예시임을 표시합니다. 실제 링크에서는 서버 상태를 조회하고 임의 도착 시간/운전자 위치를 생성하지 않습니다.
- 위치 공유는 명시적 동의 후 시작합니다. 모바일 브라우저의 백그라운드 위치/알림은 별도 검증이 필요합니다.
- Sites 게시본은 정적 미리보기이며 실제 서버와 연결되지 않습니다. 실제 차량·웹 연동은 기존 개발 서버의 초대 링크를 사용합니다.

픽업 권한 검사는 `server/domain.py`에 구현되어 있습니다. 격리된 Flask 서버에서 차량 앱과 브라우저로 초대와 탑승 흐름을 검증했습니다.

이번 범위에는 히트맵·사용자화 기능을 포함하지 않습니다. 검증 기록: `verification/mobile-web-2026-11-10/REPORT.md`.

현재 Pleos 에뮬레이터의 **함께가기 시연** 앱에서 오른쪽 위 **에뮬레이터 테스트**를 누릅니다. 가상 친구 두 명이 있는 약속을 만들고 앱에서 출발하면 위치 재생과 친구 응답이 자동으로 진행됩니다. 외부 브라우저 조작실이 필요하지 않습니다. [실행·사용 방법](demo/README.md)을 참고하세요. 내장 내비 배경 지도 미표시는 아직 해결되지 않았으며, [조사 결과](verification/oem-map-diagnosis.md)에 확인한 사실과 남은 범위를 기록했습니다.

## 바로 실행하기

프로젝트 최상위 폴더에서 Flask 가상환경을 준비하고 서버를 실행합니다.

```sh
python3 -m venv together/.venv
./together/.venv/bin/python -m pip install -r together/requirements.txt
./together/scripts/start-dev.sh
```

서버는 맥북의 `127.0.0.1:8765`에서만 열립니다. 기존 서버가 있으면 종료하거나 재시작하지 않습니다. 약속과 계정은 `together/data/together.sqlite3`에 남습니다. 브라우저 화면은 다음 주소입니다.

- 차량: <http://127.0.0.1:8765/car.html>
- 휴대폰: 차량에서 공유한 `phone.html?invite=...` 링크

브라우저의 차량·휴대폰 화면은 별개의 개발용 프로필로 연결됩니다. 브라우저 저장 공간을 지우면 해당 프로필의 접근 토큰도 사라집니다. 이 버전의 자동 기기 프로필은 개발용이며, 휴대폰 본인 인증이나 계정 복구를 제공하지 않습니다.

## Android / Pleos

Android Studio에서 `android/PickupTogether`를 엽니다. 서버를 실행한 상태에서 아래 명령으로 Pleos 가상 기기를 빌드·실행합니다.

```sh
./android/PickupTogether/scripts/run-pleos.sh
```

기존 Pleos 가상 기기가 있으면 재사용합니다. 새 가상 기기를 만드는 데 필요한 SDK 설정은 기존 프로젝트 문서를 참고합니다. 차량 기기에서는 차량 화면, 휴대폰은 새 웹 초대 링크를 사용합니다.

이미 빌드한 APK를 USB 기기에 설치할 때는 다음 명령을 씁니다. `adb devices`에 보이는 기기 이름을 지정합니다.

```sh
./together/scripts/connect-device.sh emulator-5554
```

APK: `together/artifacts/together-dev.apk`

초대 링크는 **이 맥북과 USB로 연결하고 포트를 연결한 Android 기기**, 또는 이 맥북의 브라우저에서 사용할 수 있습니다. 다른 장소의 친구에게 인터넷으로 보내 사용하는 배포 버전은 아닙니다. 같은 Wi-Fi에 있다는 것만으로 연결되지 않습니다.

앱에서 초대를 직접 열려면, 공유한 웹 주소의 `invite=` 뒤 값을 사용합니다.

```sh
adb -s DEVICE_SERIAL shell am start -a android.intent.action.VIEW -d 'togethermove://invite?token=INVITE_TOKEN'
```

개발 APK는 loopback HTTP만 허용합니다. 위치 확인에는 차량 내장 내비를 사용하며 외부 웹 지도는 로드하지 않습니다. 배포할 때는 HTTPS 서버 주소, 계정 인증, 실제 푸시 알림을 연결해야 합니다.

## 연결한 기능

- 여러 약속의 생성·수정·취소, 날짜·시간·출발지·목적지 저장
- 먼저 출발한 일행의 추정 도착에 맞춘 출발 시각과 중복 없는 알림
- 일행 이름 등록, 개인별 초대 링크 생성, 실제 수락·거절과 이동 방법 설정
- 차량 목적지는 별도 유리 검색 화면의 결과 목록에서 선택합니다. 이름·주소·좌표를 일정에 저장하고, 출발할 때 Pleos 내비에 좌표를 전달합니다. 휴대폰은 저장한 장소와 현재 위치를 사용합니다.
- 참가자의 픽업 장소·설명·준비 상태 동기화, 출발 전 픽업 순서 변경
- 운전자 출발, 수동 픽업 장소 도착 확인, 도착 알림, 양쪽 탑승 확인
- 현재 픽업 취소 시 다음 구간으로 진행. 출발 후 참가자·순서를 임의로 바꾸지 않음
- 주차장 선택, 주차 완료, 이동 종료와 기록 저장
- 일행 메시지와 고마움 메시지 저장
- 참가자가 직접 약속 장소 도착·귀가 확인. 이동 종료가 귀가 확인을 대신하지 않음
- 출발 후 켠 위치 공유, 직접 중지, 도착·종료 시 중지. 다른 사람의 출발지와 운전자의 전체 과거 위치는 공유하지 않음
- Android에서 위치 권한 확인, 실제 GPS 수신, 위치 공유 중 알림 표시, 공유 중지 동작
- Pleos NaviHelper 경유지 안내·내비 화면 열기, 실제 안내 상태와 남은 시간·거리 수신
- Pleos FusedLocation 차량 위치, TextToSpeech 상태 읽기, SpeechToText 버튼식 음성 명령
- Vehicle 지원 범위·도어·주행 거리계·좌석 점유 조회, 승차 감지 및 Gleo 앱 명령 세 가지와 공식 콜백 형식
- 주행 중 설정 제한, 서버 연결 실패·권한 거절·오래된 정보·동시 수정 충돌 처리

## 실제 정보와 추정 정보

2026-11-09부터 외부 웹 지도 렌더링을 중단했습니다. 목적지는 앱의 검색 결과 목록에서 고르고, 경로 안내와 픽업 위치 확인은 Pleos 내장 내비를 사용합니다. 픽업 대상으로 고른 사람만 하단에 순서대로 표시합니다. 위치 보기는 경로 요청이나 장소 변경을 수행하지 않습니다.

픽업 장소의 정확한 내비 POI ID를 확인할 수 있으면 POIDetailPopup을 요청합니다. 현재 저장된 좌표만으로 지도 중심을 직접 이동하는 공개 API는 확인되지 않아, POI ID가 없는 경우 SearchPlace로 내비 검색 결과를 열고 사용자가 장소를 한 번 누르는 방식입니다. 임의의 좌표를 내비 POI ID로 꾸미거나 조회만을 위해 목적지를 바꾸지 않습니다.

서버의 기본 시간 계산은 **직선거리 기반 추정**입니다. 실제 도로 안내는 차량 내비에 요청합니다. 차량 내비의 탐색 완료 또는 목적지가 일치하는 실제 경로 안내 상태가 확인되기 전에는 성공으로 처리하지 않습니다. 앱에 표시하는 내비 ETA는 현재 약속의 목적지 좌표가 일치하고 30초 이내에 수신한 값만 사용합니다. 내비에서 직접 다른 목적지로 바꾸면 이 약속과의 연결을 해제합니다. 휴대폰과 서버의 시간 계산은 기존 추정 방식이며, 차량의 내비 ETA를 휴대폰에 전송하는 기능은 아직 없습니다. 현재 공개 NaviHelper의 두 경유지 제한을 넘는 경우 다음 픽업까지만 요청하고, 탑승 후 다음 경로를 요청하도록 안내합니다. 실제 차량과 상용 내비 서버를 통한 안내 품질은 별도 검증이 필요합니다.

차량의 일정 생성 창에서 목적지 항목을 누르면 별도 검색 화면으로 이동합니다. 결과를 고르고 **목적지로 설정**을 누르면 이름·주소·좌표를 초안에 반영합니다. 이 과정에서는 내비 경로를 바꾸지 않습니다. 일정 저장 후 **출발하기**를 누르면 저장된 좌표와 지원 범위 내 경유지를 NaviHelper에 직접 전달하며, 내비에서 같은 장소를 다시 고르는 절차는 없습니다.

현재 키가 설정되지 않아 **저장된 장소와 실제 내비 최근 목적지**만 검색합니다. 서버에 `KAKAO_REST_API_KEY`가 설정되면 기존 장소 검색 연결로 외부 장소 검색 결과를 함께 사용할 수 있습니다. 카카오 지도 화면은 띄우지 않습니다. 키가 없는 현재 환경에서는 전국 장소 검색이 완료된 것으로 취급하지 않습니다.

주차장의 실시간 빈자리·현장 요금·운영시간은 연결하지 않았습니다. 요금이나 빈자리 수를 예시 값으로 표시하지 않습니다. 픽업 장소의 도로 안전성·합법적 정차 여부 자동 판정과 거리 사진도 아직 없습니다.

주행 거리는 실제 위치 공유 중 수신한 점들로 계산합니다. Android 위치는 오차 반경이 100m를 넘는 점과 비정상적인 이동을 기록하지 않습니다. Pleos 위치의 confidence를 미터 단위 정확도로 바꾸지 않으며, 정확도 반경이 없는 점은 기존 서버의 보수적인 100m 처리 기준을 적용합니다. 차선 수준 정확도를 보장하지 않습니다. 수신한 위치가 없으면 거리와 경로는 기록 없음으로 표시합니다. 위치를 공유하지 않아도 출발·탑승·완료 시각과 일행은 저장됩니다.

알림은 서버의 상태 변경과 10초 간격 출발 알림 계산을 사용합니다. 화면은 표시 중이거나 연결된 경로 안내 중에 약 2.5초 간격으로 동기화합니다. Android는 안내 중 GPS 공유와 독립적인 `GuidanceService`를 실행해 앱이 내비 뒤에 있어도 동기화를 유지합니다. 이 서비스는 위치 권한을 요청하거나 위치를 수집하지 않으며, 경로 연결 해제·여정 종료·취소 시 종료합니다. 앱을 완전히 종료한 기기에 모든 알림을 보내는 FCM/APNs는 연결하지 않았습니다.

경로 안내 시작 직후에는 패널을 띄우지 않습니다. 현재 구간의 최신 내비 예상 시간이 10분 초과에서 10분 이하로 바뀌거나 도착·준비 완료 등 필요한 상태 변화가 있을 때 오른쪽 상단 유리 패널을 표시합니다. 패널은 7초 뒤 자동으로 닫히며 검정 진행 막대가 남은 표시 시간을 나타냅니다. 기존 15초 테스트 알림은 제거했습니다.

차량 화면은 홈·주행 기록 탐색, 등록된 친구 목록 기반 일행 추가, 지도 영역 없는 전체 여정 화면으로 통일했습니다. 일정 생성·검색·친구 선택·안내 패널에는 Android 창의 실제 배경 흐림을 적용합니다. 주차장은 별도 선택 페이지를 만들지 않고 목적지 선택에 포함합니다.

선물·쿠폰의 실제 구매·결제·전송과 집 주소 기반 자동 귀가 감지는 없습니다. 고마움은 일행 메시지로 전달합니다. 공유 대상은 이번 약속 참가자 전체이며, 사람별 선택이나 별도의 종료 시각은 제공하지 않습니다.

차량 앱에서 **출발하기**를 누르면 출발을 기록한 뒤 내장 내비를 열어 안내를 요청합니다. 이미 이동 중이면 **다음 경로 안내**를 누릅니다. 차량의 **기기와 권한**에서도 내비를 열 수 있습니다. 이동 화면에는 **다음 경로 안내 / 음성 명령 / 내비 열기**가 있습니다. 내비 안내는 기존 내비 앱이 담당하며, 앱 안에서는 외부 미리보기 지도를 표시하지 않습니다. Pleos의 고정 내비 창을 재사용하고 함께가기의 창을 잠시 숨깁니다. 시스템의 함께가기 아이콘을 누르면 저장된 약속 화면으로 돌아옵니다. 새 내비 Activity를 중복 생성하지 않습니다. 내비 지도 위에 상대방 마커나 위젯을 삽입하는 기능은 없습니다.

음성은 `ON_DEVICE` 모드를 사용하며 프로젝트 비밀 키를 APK에 넣지 않습니다. `음성 명령`을 누르고 “픽업 상태”, “내비 안내”, “도착 알려줘”, “위치 공유 중지”를 말할 수 있습니다. 부분 인식 결과로는 실행하지 않고, 경로·알림·공유 변경은 화면에서 한 번 확인합니다. 화면을 벗어나면 인식을 중지하며 항상 듣는 기능은 없습니다. 실제 마이크 인식 품질은 별도로 확인해야 합니다.

FusedLocation은 Android 위치 권한 외에 `pleos.car.permission.FUSED_LOCATION` 런타임 권한을 요청합니다. 거절해도 기본 기기 위치를 사용할 수 있습니다. 차량 개인정보 설정으로 위치 접근이 차단된 경우 이를 우회하지 않습니다. 도어 값으로 탑승자 신원을 판정하거나 탑승을 자동 완료하지 않습니다. 거리계 원시 값은 연결 확인에만 사용하고, 기록 거리는 기존 GPS 방식으로 계산합니다.

Gleo에 등록할 함수는 공식 제한에 맞춰 세 개입니다.

- `GET_PICKUP_STATUS`: 선택한 진행 중 약속의 상태와 다음 픽업 대상 조회

## 좌석 점유로 승차 확인

차량의 좌석 점유 및 문 상태는 Pleos Vehicle 2.3.2의 읽기·구독 API를 사용합니다. `CAR_SEATS`와 기존 `CAR_DOORS` 권한 및 지원 좌석을 확인하고, Android의 차량 정보에서 실제 운전석 위치를 읽어 운전석을 제외합니다. 값을 읽지 못하면 빈 좌석으로 간주해 승차를 확정하지 않습니다.

자동 승차는 현재 안내와 연결된 운전자 일정에서, **현재 픽업 장소 도착 상태이고 해당 일행이 준비 완료/대기 중일 때**만 적용합니다. 도착 상태에 들어온 뒤 한 동승자 좌석이 빈 상태에서 점유 상태로 바뀌고 1.5초 이상 유지되며, 해당 문을 열고 닫은 변화가 함께 확인돼야 합니다. 차량이 이동 제한 상태이거나, 센서가 오래됐거나, 운전석을 알 수 없거나, 여러 좌석이 동시에 바뀌면 자동 처리하지 않습니다. 기존 수동 탑승 확인은 유지합니다.

성공하면 기존 서버의 탑승 처리를 한 번 실행하고, 남은 경유지로 내비 경로를 다시 요청합니다. 오른쪽 상단에 **이름 님 승차 완료 / 다음 이름 님에게 이동 중** 패널을 7초 표시합니다. 마지막 픽업 후에는 목적지 이름을 표시하며 전화 버튼은 숨깁니다. 좌석 센서가 사람의 신원을 판별하는 기능은 아니며 현재 픽업 순서와 도착 상태로 연결한 결과입니다.

2026-11-09 검증: Pleos 에뮬레이터에서 실제 좌석·문 상태 수신을 확인했습니다. 센서 값을 외부에서 변경하는 VHAL 입력이 반영되지 않아, 빈 좌석→점유 및 문 여닫힘 변화는 앱 이벤트 경계에 모의 입력을 넣어 검증했습니다. 서버의 탑승 기록, 다음 경유지 전달, 최종 목적지 전환과 유리 패널을 실제 앱에서 확인했습니다. 실차 승차 감지 성능은 검증하지 않았습니다. 자료는 `verification/seat-boarding-2026-11-09/`에 있습니다.

### 자동 승차와 좌석 설정 (2026-11-11)

현재 픽업 위치 80m 이내에서 새로 착석한 동승자 좌석을 감지하면 수동 준비 확인 없이 바로 승차를 기록합니다. 승차 판정에는 P단·속도·2분 제한·3초 유지 조건을 사용하지 않습니다. 문 열림은 필수 조건이 아닙니다. 실제 좌석 설정은 별도로 P단 정차·점유를 확인한 후 적용하고 남은 픽업/목적지 안내를 갱신합니다. 앱 화면이 OEM 내비 뒤에 있어도 네이티브 서비스가 처리합니다. 설정은 휴대폰 초대 웹의 내 정보에서 한 번 저장합니다. 좌석 자세 복원은 해당 차량/좌석이 지원하는 하드웨어 메모리 번호를 등록한 경우에만 요청합니다.

같은 관찰에 여러 좌석이 새로 점유된 경우·기존 점유·운전석·확인할 수 없는 센서는 자동 연결하지 않습니다. 운영 모드에서는 확인할 수 없는 위치도 자동 연결하지 않습니다. 에뮬레이터 시험은 좌석/정차 SDK 신호를 사용하고 위치만 시험값으로 통제했습니다. 실제 GPS 근접/실차 기계 구동 완료 검증과는 구분합니다. 시험 방법과 세부 결과는 `verification/auto-pickup-2026-11-11/TRY-IT.md`, `REPORT.md`를 참고하세요.


시연 서버를 `POOLY_PICKUP_REQUIRE_PROXIMITY=0`으로 시작하면 GPS/80m 검사만 생략합니다. 기본값은 `1`이며 운영 서버와 PythonAnywhere에서는 그대로 유지합니다. 서버가 `/api/state`의 `auto_pickup_proximity_required`로 정책을 내려 주며 클라이언트 요청으로 임의 변경할 수 없습니다. 시연에서도 실제 좌석 신호, 현재 픽업 순서, 운전자 권한, 중복 방지 검사는 유지합니다. 이미 실행 중인 서버에는 재시작 후 적용됩니다. 최신 조건과 검증은 `verification/pickup-simple-2026-11-11/REPORT.md`를 참고하세요.


### 브이월드 검색과 휴대폰 픽업 히트맵 (2026-11-11)

장소 검색은 VWORLD_API_KEY 설정 시 브이월드 검색 API 2.0을 우선 사용합니다. 장소/주소 결과를 좌표와 함께 선택해 Pleos 목적지로 전달합니다. 서버 전용 설정은 together/data/private/search-provider.json 또는 POOLY_SEARCH_CONFIG 환경변수의 JSON 경로에 보관하며 배포 ZIP에는 포함하지 않습니다. 운영 환경은 VWORLD_DOMAIN도 실제 서비스 URL로 설정합니다.

휴대폰 웹 하단 ‘픽업 지도’에서 가상 집계 히트맵을 확인할 수 있습니다. 실제 픽업 기록 분석이 아니며 예시 표시를 유지합니다. 픽업 위치 설정에서도 예시 레이어를 켜고 끌 수 있습니다. 위치는 지도 클릭 좌표로 정하므로 별도 검색 API를 쓰지 않습니다. 내비 위 일정/검색 패널은 소프트 키보드가 올라와도 크기와 위치를 유지합니다. 검증 결과는 verification/vworld-heatmap-2026-11-11/REPORT.md를 참고하세요.

차량 검색 결과 선택 시 Pleos 내비의 장소 검색 화면도 열립니다. 자체 Pleos POI ID가 있는 장소는 상세 팝업을 요청합니다. 검색창 하단 제공자 안내 및 결과의 위치 아이콘/제공자 문구는 제거했습니다. 브이월드 좌표로 내비 지도를 직접 이동하는 기능은 공개 SDK에 없어 검색 결과를 한 번 더 눌러야 할 수 있습니다. 검증: verification/destination-preview-2026-11-11/REPORT.md.
