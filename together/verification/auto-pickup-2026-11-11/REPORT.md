# 자동 승차 · 좌석 사용자화 — 2026-11-11

## 구현
- Android의 GuidanceService가 내비 위로 앱이 가려져도 PickupAutomation을 실행합니다. 웹 타이머 기반 자동 승차와 중복 실행하지 않습니다.
- 현재 픽업 대상/일정과 내비 연결을 확인하고, 내비 위치 80m 이내 · P 기어 · 속도 0.3m/s 이하인 경우 도착을 기록합니다.
- 도착 후 120초 안에 새로 발생한 비점유→점유 전이가 3초 유지되면 해당 좌석을 현재 픽업 대상과 연결합니다. 문 개폐나 수동 준비 상태는 필요하지 않습니다.
- 운전석, 초기부터 점유된 좌석, 오래된/미확인 센서, 다른 경로, 동시에 바뀐 복수 좌석은 자동 연결하지 않습니다.
- 서버는 운전자 권한, 현재 대상자, 근접/정차/시간 조건 및 중복 관찰 ID를 검증합니다. 같은 신호 재전송은 다음 사람을 승차 처리하지 않습니다.
- 확인된 승차에만 사용자 프로필을 조회하고, 남은 픽업과 최종 목적지로 내비 요청을 갱신합니다. 승차 알림은 기존 7초 표시 UI를 사용합니다. 차량을 직접 운전하거나 문을 여는 명령은 보내지 않습니다.

## 사용자 설정
- 휴대폰 초대 웹 → 내 정보 → 내 좌석 설정에서 자동 적용, 추울 때 열선, 더울 때 통풍을 저장합니다. 기본은 자동 적용 꺼짐입니다.
- 실제 실내 온도(℃)가 20 이하이면 저장한 열선 단계, 26 이상이면 통풍 단계, 그 사이는 둘 다 끕니다. 온도를 읽지 못하면 설정을 추정해서 적용하지 않습니다.
- 지원 범위/쓰기 권한/좌석 영역을 조회하고 해당 동승자 좌석만 제어합니다. 비동기 호출 때마다 정차와 점유 상태를 다시 확인합니다.
- 각도/자세는 현재 차량에 미리 저장된 좌석 메모리 슬롯을 재호출하는 방식입니다. 승차 이력이 있는 차량에 한해 사용자가 번호를 저장합니다. 차량이 해당 좌석의 메모리를 지원하지 않으면 건너뜁니다. 차량 간 원시 각도 수치를 복사하거나 모터를 시간만큼 구동하지 않습니다.
- 개인 설정은 사용자별 SQLite 테이블에 저장하며 다른 동승자의 프로필을 직접 조회할 수 없습니다. 차량 식별에는 VIN 대신 이 앱 설치에 보존되는 무작위 키를 씁니다.

## 검증
- Python API 테스트 총 30개: 기존 25개와 자동 승차/개인 프로필 API 테스트 5개 통과.
- Kotlin 승차 정책 테스트 7개 통과(문 없는 전이, 3초 안정화, 운전석/기존 점유/복수 좌석/주행/오래된 위치 거부, 온도별 판단).
- Pleos 2.1.0 에뮬레이터 + SDK 2.3.2 공식 콘솔의 Passenger Empty→Occupied가 실제 SDK ROW_1_RIGHT 변화로 들어와 서버 승차와 좌석 연결, 다음 목적지 요청까지 통과했습니다. 문은 모두 닫힌 상태였습니다.
- SDK 권한을 실제 검증 중 CAR_CLIMATE 및 CONTROL_CAR_SEATS로 수정했습니다. 실내 19.1℃ 조회, 동승자 열선 1단계 적용 응답 및 콘솔 H1 표시 확인.
- 휴대폰 웹에서 설정 저장 후 새로고침해 자동 적용 켜짐/열선 2단계/통풍 1단계 유지 확인. 캡처: seat-preferences.png.
- 내비/GPS 자체의 기존 에뮬레이터 문제를 분리하기 위해 시험의 위치/일정 연결만 테스트 입력을 사용했습니다. 좌석/정차 신호는 실제 SDK입니다. 실차 GPS 근접 판별과 좌석 기계 구동 완료는 검증하지 않았습니다. 공개 메모리 API는 실패 콜백만 있어 성공 시 '요청됨'으로 기록합니다.
- 에뮬레이터/SDK 버전에 한정한 기존 점유 Boolean 호환 처리는 유지합니다. 이 결과를 다른 버전 또는 실차 동작으로 일반화하지 않습니다.

## 배포와 데이터
- 사용자의 명시적 승인 후 8765 개발 서버를 같은 DB로 재시작했습니다. 재시작 전 SQLite 일관성 백업을 저장하고, 기존 일정 문서 전체 해시 및 사용자 수가 동일함을 확인했습니다(일정 2개/사용자 2명).
- 자동 시험 데이터는 /tmp/pooly-auto-pickup-sdk-20261111.sqlite3 및 검증용 별도 앱에서만 생성했습니다. 기존 일정은 초기화하지 않았습니다.
- 기존 지도 문제를 해결했다고 주장하지 않습니다. 개인화와 경유지 변경은 현재 SDK가 제공하는 신호와 지원 여부에 따릅니다.
