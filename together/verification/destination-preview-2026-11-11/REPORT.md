# 목적지 검색 결과와 내비 연결

## 변경
- 차량 검색 화면에서 검색창 하단 제공자 안내 삭제. 오류가 있을 때만 별도 안내.
- 결과 카드의 왼쪽 위치 아이콘과 제공자 텍스트 삭제. 장소명·주소·선택 체크 유지, 본문 너비/높이 조정.
- 결과 행 선택 시 기존 previewNavigationPlace 브리지로 Pleos 내비 화면 요청. 앱의 목적지 선택 상태와 일정 초안은 그대로 유지.
- 실제 Pleos POI ID가 있는 경우 상세 팝업 요청. 브이월드 결과는 내비 장소명 검색 화면을 열고, 주소 결과는 주소로 검색. 브이월드 ID를 Pleos POI ID로 전달하지 않음.
- 경로 요청/경유지 추가/안내 시작은 수행하지 않는 보기 동작.
- 새 검색 입력·뒤로가기·생성 취소 시 대기 중인 미리보기와 지연 화면 요청 취소. 늦은 응답으로 다른 화면이 갑자기 열리는 것 방지.

## SDK 제한
- 설치된 NaviHelper 3.0.5와 공개 API 목록에서 임의 위경도에 지도 중심을 옮기는 화면 요청은 없음.
- POIDetailPopup은 Pleos 자체 poiId/poiProvider를 요구. 외부 검색 결과의 좌표/ID만으로 동일한 장소 상세를 직접 열 수 없음.
- 따라서 브이월드 검색 결과를 선택하면 내비 검색 목록까지 열림. 지도에서 특정 장소의 상세 위치를 확인하려면 내비 결과를 한 번 더 선택해야 할 수 있음. 정확한 좌표 핀 미리보기를 구현했다고 주장하지 않음.
- 기존 OEM 배경지도 미표시 문제를 해결했다는 의미가 아님.

## 검증과 적용
- 일반·시연·integration·androidTest APK 빌드 성공.
- 실제 에뮬레이터 계측 시험 1개 통과: 실제 키보드에서 패널 bounds/배율 고정 → 브이월드 실검색 → 삭제된 UI 요소 없음 → 결과 선택 → native SearchPlace 요청 확인 → 기존 안내 목적지 상태 유지 → 일정 폼에 목적지 설정.
- destination-preview.png에서 실제 내비 성수역 검색 결과 목록과 오른쪽의 정리된 선택 패널 확인. instrumentation.log/native-events.log 참고.
- 일반 APK 데이터 삭제 없이 업데이트 설치, 서버8765 재시작하지 않음. 기존 사용자 수와 일정 문서 해시 동일.
- 시험은 별도 앱/임시 DB59583에서 수행. 시험용 앱 제거, 키보드 설정 복원, 일반 앱 복귀.
